## Existing improvements and intervening changes

The reference already used source-faithful joint-reserve whole-horizon scheduling,
guarded consumer dominance, same-attempt hourly primal continuation, full
same-hour primal/dual starts after shunt rounding, bounded adaptive-barrier
recovery and independently audited feasible-point stopping. Original temporal
constraints, startup windows, P/Q capability and reserve headroom remain.

Between `cfe7ea0` and `0b58e78`, optional cold commitment construction and a
restricted cost LP were added for the failed 6,717-bus case. Cache-only domain
transitions, explicit IPX selection, early seed checkpoints and finer scheduling
events were subsequently tested. **These optional numerical phases are disabled
in this speedup configuration.** Source retrieval limits and failure/timing
reporting also changed. No newer AC numerical method preceded this branch.
This experiment nevertheless changes multiple search/control policies and uses
newer orchestration: it is **not an isolated single-factor ablation**.

## Smallest coherent first variant

1. Keep the cold whole-horizon source-reserve scheduling MILP, simplex relaxations,
   and 1e-3 gap. Reduce its requested native time ceiling from 3,600 to 600 s
   to fit the new global budget; the saved successful native/API solve was well
   below that ceiling. No old solution, basis, dual, POP or competitor point is read.
2. Initialize voltage from source conditions, shifting all source angles by the
   same amount to honor the unchanged reference-angle equation. Evaluate exact
   branch flows from those voltages, impedances, taps and phase shifts. This is
   network-aware dispatch initialization, not a power-flow feasibility claim.
   Later starts come only from the preceding locally screened hour in this attempt.
3. Try the current valid integral shunt settings first. Form short LP corrections
   on the original hourly AC model: keep every affine row, original bounds,
   PWL coefficient and reserve/capability row; linearize nonlinear rows using
   their exact sparse analytic Jacobian. Trust regions limit voltage/angle
   steps, not source limits. HiGHS receives the matrix in one bulk CSC transfer.
4. Re-evaluate the ORIGINAL nonlinear equations, affine constraints and bounds
   after each trial. Backtrack rejected large steps, retain only residual-reducing
   steps, and roll back failures. The cached numeric residual is cross-checked
   against JuMP's original-expression feasibility report before returning.
   Success is local feasibility at the unchanged 1e-8 screen, not optimality.
5. If needed, give the complete same-attempt point to one short Ipopt/MUMPS
   fixed-shunt fallback. A small source-domain continuous-shunt revisit followed
   by integral rounding and fixed-setting repair is allowed only if time remains.
   The relaxed setting itself is never an accepted discrete output. Worsening
   revisits roll back. No hour is accepted solely on a solver status.
6. Keep hours sequential. Whole-horizon commitment, startup/shutdown trajectories
   and startup windows come from scheduling. Forward/backward ramp envelopes and
   bounds from the immediately preceding accepted dispatch constrain hourly
   changes. The registered case has no unsupported energy-window/startup-state
   features; the existing feature gate still rejects them rather than omitting them.
   Full-horizon temporal validation remains mandatory after all postprocessing.
7. Reuse the already computed joint-scheduling reserve awards for the explicitly
   unverified intermediate checkpoint, skip its expensive exhaustive evaluation,
   and write fewer large checkpoints. Reallocate final reserves as before and
   protect complete independent plus official verification. An unfinished horizon
   is retained as UNVERIFIED rather than spending minutes evaluating it as if done.

The initial commitment is still selected by the aggregate source-faithful MILP;
this first variant adds network-aware dispatch correction, not network-aware
commitment search or parallel blocks. Jacobian structure is reused within each
correction loop. Native LP factorization/basis reuse is not claimed. Complete
native LP start storage is observed; use after presolve is not asserted.

Inherited candidate-search restrictions remain explicit: source branch topology
and transformer settings are fixed; base balance slacks are zero in the hourly
candidate model to pursue the physical-feasibility gate. This is not a change to
official GO3 soft-violation semantics. In particular, base thermal violations,
contingency penalties and reserve shortages are NOT made hard-zero or discarded.
Their unchanged original penalties are included in final evaluation and reported.

Expected benefit: fewer lengthy nonlinear solves and less intermediate overhead.
Risks: linearized LPs can be infeasible or too slow; nonlinear steps may stagnate;
fixed shunts can need revisiting; dispatch changes can reduce score or expose
temporal/contingency violations. No claim of a full GO3 bound or optimality is made.
Unchanged independent/official evaluation rejects these failures.

## Registered boundary and stopping rule

Exactly one attempt: `speedup_n06049_s003_r01`, 6,049 buses, scenario 003,
48 one-hour intervals, all 3,902 source contingencies per interval.
Hard end-to-end **1,800 s**, including raw loading, process/JIT, model construction,
all internal iterations/fallbacks, checking and serialization. Reserve **450 s**
for final verification (earlier saved checks exceeded 300 s), **30 s** for
serialization, and 90 s inside the work budget for final reserve/postprocessing.
No required numerical work is moved outside the measured boundary.

Correction limits: 45 s per hourly call, at most 15 s for the initial linear
correction loop, at most eight rounds, at most 8 s per LP, and a 12 s requested
Ipopt fallback. Every limit is intersected with the same absolute work deadline.
Native operations may finish between checks; the owned-process watchdog enforces
the global deadline. One Julia worker, one BLAS thread, four HiGHS threads;
no parallel hourly models, GPU, new package, or commercial solver.

Preflight budget assessment: mandatory scheduling, raw/process overhead, final
reserves and verification can fit under 1,800 s using the saved evidence, but
leave only roughly 12 minutes for AC work. This requires a substantial reduction
from the baseline's 86.5-minute AC stage. It is an experiment, not a promise of
30-minute success or 5–10-minute turnaround. The latter would require additional
work on scheduling and verification too.

Before launch: complete tiny/component tests, freeze/push the exact revision,
and claim the immutable one-run latch. After this ONE full run, archive its
evidence and report every failed gate, score tradeoff, timings and resource use.
No automatic replacement, parameter sweep, baseline repetition or other network
run is authorized. Stop for user review afterward.

## Single full experiment: failed adapter gate, stopped for review

The one registered attempt ran at **`722362a3b97742958c42b8f687ca030b7febe7f8`**
and ended after **570.953992 s** with `NO_VERIFIED_INCUMBENT`. It did not time
out. The scheduling MILP passed its requested gap; hour 1 then aborted during
the first correction LP import. No correction LP was optimized, no Ipopt
fallback ran, and no AC hour was accepted. The incomplete schedule was retained
as UNVERIFIED. Final exhaustive evaluation was intentionally not run on it.

The immediate implementation bug is the check at `src/ac_correction.jl:98`:
only `kHighsStatusOk` is accepted. At line 114, `Highs_passLp` returned **1**,
which the installed HiGHS wrapper defines as **`kHighsStatusWarning`**, not
`kHighsStatusError` (-1). The adapter promoted that warning to an exception.
Native output was disabled, so the precise warning text was not preserved.
The logs do **not** establish which coefficient/bound caused the warning,
whether import made a material numerical change, or whether a solve would
have succeeded. No infeasibility or speed-benefit conclusion follows.

The tiny tests missed this import-warning path. This was an adapter robustness
gap, not evidence that the full case passed the new method. No full diagnostic
replay, replacement, parameter change, or subsequent network was launched.
All task-owned Julia/controller processes were confirmed exited after failure.
