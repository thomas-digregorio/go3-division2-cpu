## Change from the failed r01 implementation

At numerical revision `722362a`, r01 stopped after 570.953992 seconds because
`Highs_passLp` returned warning status 1, which the adapter incorrectly treated
as fatal. Native warning text was suppressed. The scheduling MILP had met its
requested gap and exactly reproduced the reference scheduling commitment/P/Q
dispatch, but no correction LP solve or AC-hour acceptance occurred.

The replacement keeps the same mathematical/source models, cold scheduling
method, 1e-3 scheduling gap, source-derived costs/benefits/penalties, temporal
coupling, reserve/reactive constraints, shunt policy, short correction/fallback
budgets, and original nonlinear/final acceptance checks. It changes the adapter:

1. Persist each native LP log and JSON call record under the owned run directory,
   including on errors. Distinguish native errors (-1), warnings (1), and OK (0).
2. Use HiGHS's smallest supported `small_matrix_value`, 1e-12 rather than its
   1e-9 default, to retain more small candidate-Jacobian coefficients. This is
   an import setting, not a relaxation of original feasibility tolerances.
3. Read the unpresolved native LP back. Require exact objective coefficients,
   objective sense, row/column bounds, and dimensions. Never silently turn a
   finite source/candidate bound into infinity.
4. If native import removes tiny matrix entries, allow continuation only when
   they are the only matrix differences, every removed entry is at most 1e-12,
   and the conservative sum `sum_j |delta_A_ij| max(|lb_j|, |ub_j|)` is at most
   1e-10 for every row. An affected unbounded variable fails this audit. These
   are explicitly logged candidate-linearization import effects, not alterations
   to the original JuMP/source model. Original nonlinear residual checks remain
   mandatory and unchanged.
5. A rejected import returns no LP proposal, retaining the current point and
   permitting the existing bounded Ipopt fallback. A true native error still
   fails with retained diagnostics. No unknown warning is blindly treated as
   evidence of feasibility.
6. Charge matrix transfer/audit against each LP call's local budget and record
   native versus API versus total call time. Complete primal start storage is
   checked; algorithmic start use after presolve is not claimed.

This does not prove which warning occurred in r01; its missing warning text
cannot be reconstructed from the retained result. Tiny regression cases now
explicitly cover warnings from removed small coefficients, harmful bounded and
unbounded coefficient effects, finite-bound normalization, true native errors,
retained diagnostics, and the OneDrive path guard. Ordinary text reporting a
primal-dual objective error is not counted as a warning.

The prior candidate-search restrictions remain explicit: fixed source topology
and transformer settings, and zero base-balance slacks in the hourly candidate
search to pursue physical feasibility. Official GO3 soft penalties are unchanged.
No GPU, commercial solver, parallel hourly models, cached competitor/baseline
solution, or source modification is introduced.
