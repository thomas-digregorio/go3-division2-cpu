## Change from the failed r01 implementation

At numerical revision `722362a`, r01 stopped after 570.953992 seconds because
`Highs_passLp` returned warning status 1, which the adapter incorrectly treated
as fatal. Native warning text was suppressed. The scheduling MILP had met its
requested gap and exactly reproduced the reference scheduling commitment/P/Q
dispatch, but no correction LP solve or AC-hour acceptance occurred.

The replacement keeps the same mathematical/source models, cold scheduling
method, 1e-3 scheduling gap, source-derived costs/benefits/penalties, temporal
coupling, reserve/reactive constraints, shunt policy, short correction/fallback
budgets, and original nonlinear/final acceptance checks. It changes the adapter:

1. Persist each native LP log and JSON call record under the owned run directory,
   including on errors. Distinguish native errors (-1), warnings (1), and OK (0).
2. Use HiGHS's smallest supported `small_matrix_value`, 1e-12 rather than its
   1e-9 default, to retain more small candidate-Jacobian coefficients. This is
   an import setting, not a relaxation of original feasibility tolerances.
3. Read the unpresolved native LP back. Require exact objective coefficients,
   objective sense, row/column bounds, and dimensions. Never silently turn a
   finite source/candidate bound into infinity.
4. If native import removes tiny matrix entries, allow continuation only when
   they are the only matrix differences, every removed entry is at most 1e-12,
   and the conservative sum `sum_j |delta_A_ij| max(|lb_j|, |ub_j|)` is at most
   1e-10 for every row. An affected unbounded variable fails this audit. These
   are explicitly logged candidate-linearization import effects, not alterations
   to the original JuMP/source model. Original nonlinear residual checks remain
   mandatory and unchanged.
5. A rejected import returns no LP proposal, retaining the current point and
   permitting the existing bounded Ipopt fallback. A true native error still
   fails with retained diagnostics. No unknown warning is blindly treated as
   evidence of feasibility.
6. Charge matrix transfer/audit against each LP call's local budget and record
   native versus API versus total call time. Complete primal start storage is
   checked; algorithmic start use after presolve is not claimed.

This does not prove which warning occurred in r01; its missing warning text
cannot be reconstructed from the retained result. Tiny regression cases now
explicitly cover warnings from removed small coefficients, harmful bounded and
unbounded coefficient effects, finite-bound normalization, true native errors,
retained diagnostics, and the OneDrive path guard. Ordinary text reporting a
primal-dual objective error is not counted as a warning.

The prior candidate-search restrictions remain explicit: fixed source topology
and transformer settings, and zero base-balance slacks in the hourly candidate
search to pursue physical feasibility. Official GO3 soft penalties are unchanged.
No GPU, commercial solver, parallel hourly models, cached competitor/baseline
solution, or source modification is introduced.

(9 min 42.536 s)** with `NO_VERIFIED_INCUMBENT` and worker return code 1.

### What the new diagnostics establish

1. **The r01 import-warning bug is fixed.** Native import returned warning 1,
   but exact dimensions, domains and objective passed readback. HiGHS removed
   252 stored matrix entries, of which only four were nonzero. The largest
   removed coefficient was 7.741860784122377e-14; the conservative maximum row
   effect was 1.5483721568244753e-11, below the registered 1e-10 audit limit.
   Original source equations and final tolerances were not modified.
2. **The LP solve itself encountered a distinct numerical failure.** The native
   log reports `Solving LP with useful basis so presolve not used`. Despite no
   explicit basis supplied by this adapter, a complete primal vector was stored
   through `Highs_setSolution`. The log then shows enormous intermediate values:

   ```text
   Iteration 0: objective 6.9886218898e+53
   Iteration 0: objective 2.2089382823e+52, Pr: 55605(7.47038e+59)
   Model status: Unknown
   ```

   Native status 15 is **Unknown**, not Infeasible (8) or TimeLimit (13). The
   call ended in 0.658188 native seconds with zero simplex iterations and no
   feasible returned point, well before its 3.910000-second native allowance.
   No linear-correction step was accepted. This supports investigating the
   start-derived basis/presolve path and conditioning; it does not isolate which
   one caused failure. The first root cause is not proven by this single run.
   Recorded ranges were matrix 7e-11 to 8e4, objective coefficients 0.1 to 3e6,
   and right-hand-side magnitudes 1e-18 to 2e3. Warnings about large costs and
   small row bounds are retained, not treated as infeasibility certificates.
3. **The bounded fallback was too short to recover this point.** Ipopt performed
   24 iterations and reached its local 12-second wall-time setting (12.880
   solver-reported seconds; 21.299 seconds including setup, transfer and audits).
   The local maximum original-model residual decreased from 84.0000000007 to
   24.7566235948, still far above 1e-8. Keeping this lower-residual point is not
   accepting it as feasible. The feasible-point guard never requested a stop.
4. **The global extension did not extend the local correction policy.** Hour 1
   had a 45-second local allowance, 15 seconds for initial linear corrections
   and 12 seconds for fallback. Model initialization took 5.457 s; the correction
   oracle took another 10.195 s, inside its 13.798-second phase. That left only
   4.044 s for the attempted LP, although the LP failed numerically before using
   that allowance. The hour's recorded work was 45.234 s and no optional shunt
   revisit occurred. The fail-fast rule then stopped while about **110 minutes
   of the global ceiling remained**. Simply increasing the global ceiling cannot
   repair this numerical issue or override these fixed local budgets.

The complete native text remains under the retained run at
`worker/native_correction/hour_0001/jl_29A8.tmp` (SHA256
`3867f7117e0e6e98e752f5d6763cc59f1085a8ccd52f601b809e1c82c3815281`).
Its compact JSON import/start/timing audit is also included in the tracked
evidence. `basis_reused=false` means no earlier basis was explicitly reused;
it does not contradict HiGHS internally constructing/using a basis after the
primal-start call. Stored-vector acceptance is not proof of a useful numerical
start, successful optimization, or full GO3 feasibility.
